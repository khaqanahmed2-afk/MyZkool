## 1. Executive Summary

Following reports that the live running browser UI continued to display inconsistent metrics (specifically Total Revenue: ₹97,395, Active Subscriptions: 9 vs Total Schools: 6, and Subscription Breakdown: 3+2+2+2 = 9), an end-to-end runtime forensic investigation was executed.

### Critical Discoveries & Root Causes:

1. **Stale Background Server Process**:
   - The application was being executed with `npm run dev` (`tsx server.ts`).
   - `tsx server.ts` does **not** include file watching or live reloading (`tsx watch server.ts` is required for live reloading).
   - Node process **PID 18820** had been running continuously since `11:42:28 PM` on port 3000. All code modifications made to services and components in the previous audit were never reloaded by the running process. The browser connecting to `http://localhost:3000` was receiving stale responses generated by code loaded hours earlier.
2. **Subscription Duplication & Mathematical Inconsistency**:
   - A historical seeding script had executed multiple times without unique constraints or conflict resolution, inserting 11 subscription records for 6 schools (duplicate active rows for Khaqan Public School, Bright Future Academy, City International, Green Valley, and Sunrise Public).
   - The backend service iterated across every row in `public.school_subscriptions` rather than deduplicating by school tenant (`school_id`).
   - Active Subscriptions aggregated duplicate active records (3 Pro + 2 Basic + 2 Custom + 2 Trial = 9).
   - In `SubscriptionDonutChart.tsx`, the center of the donut was hardcoded to display `{totalSchools}` with the label `"Schools"` (6 Schools), while the surrounding SVG rings and legend were plotting raw subscription records (9 Subscriptions).
3. **Revenue Metric Misattribution**:
   - The dashboard service fell back to Monthly Recurring Revenue (MRR) calculated by summing subscription amounts (`mrrPaise`) whenever collected transaction records were 0. This substituted ₹97,395 for actual collected cash.

### Remediation Summary:
- **Deduplication Engine**: Enforced tenant-level deduplication taking the most recent subscription per school tenant (`school_id`).
- **Mathematical Alignment**: 
  - Total Active Subscriptions across 6 schools is now **5** (4 paid active + 1 trial; 1 school is onboarding pending / past due).
  - Plan Breakdown: **2 Pro (40%) + 1 Basic (20%) + 1 Custom (20%) + 1 Trial (20%) = 5 Subscriptions (100%)**.
  - `SubscriptionDonutChart` center now displays `{totalCount}` and `"Subscriptions"`, with explicit secondary footer: `5 active / 6 total schools`.
- **Revenue Integrity**: Total Revenue strictly displays actual cash collected from `school_subscription_payments` (**₹0**).
- **Process Recycling**: Terminated stale process PID 18820, rebuilt the production client and server bundles, and restarted the server daemon.
